## QUÉ ES

ERP clínico para clínicas en México (Centro Médico Santa Cruz). UI 100% en español.
Tres superficies: web (Vite), desktop (Tauri 2, shell sin lógica Rust) y Android
(Capacitor 6 WebView que carga producción). Versión package.json: 1.3.10.

## STACK

- Frontend: React 19, Vite 7, React Router 7, Tailwind 3, JavaScript/JSX (sin TypeScript)
- Iconos: lucide-react (principal), @phosphor-icons/react (admin)
- Backend: Firebase 12 — Auth email/password, Firestore, Storage, Cloud Functions
- Proyecto Firebase: srs-feacb — src/config/firebase.js exporta auth, db, storage, functions
- IA: Gemini / Vertex AI vía Cloud Functions (askGemini y otras)
- PDF: @react-pdf/renderer (principal); html2canvas + jspdf / html-to-image (fallback)
- Excel: xlsx. Búsqueda: Meilisearch (cliente existe; sync NO cableado al CRUD)
- No hay React Query/SWR, tests automatizados ni React.lazy
- StrictMode DESACTIVADO en main.jsx (bug Firestore INTERNAL ASSERTION FAILED)

## AUTH Y SESIÓN

AuthContext expone: { user, login, logout, loading, profileError, retryProfile, cambiarEstadoOperativo }

1. signInWithEmailAndPassword
2. Perfil users/{uid} con getDoc (timeout 4s) + onSnapshot
3. user = Firebase Auth + todo el documento Firestore (rol, permissions/permissionList,
   statusOperativo, isOnline, lastSeen, sessionSucursal*, sessionConsultorio*, …)
4. Cache localStorage srs_auth_profile_cache_v1
5. Hidratado si hay rol o permisos
6. Logout: gracia 250 ms sin cache / 1500 ms con cache
7. Idle 30 min (src/utils/sessionIdle.js); heartbeat cada 2 min (lastSeen, isOnline, asistencia_diaria)
8. Splash hard-stop 8 s

Signup público bloqueado: beforeUserCreatedBlockPublicSignup + allowlist auth_registro_permitido.
Alta de staff: crearUsuarioStaff.

SessionLocationContext: sucursal/consultorio de sesión. Catálogos catalogo_sucursales +
catalogo_consultorios. Persistencia en users/{uid} y sessionStorage srs_loc_confirmed_{uid}.
Gate: WelcomeLocationGate.

FirebaseErrorContext: permission-denied → FirebasePermissionSupportModal.

Rutas:
- GuestRoute: login; si hay sesión → /inicio
- PermissionRoute: hasPermission(user, permissionId, fallbackRoles); si no → /inicio.
  permissionId puede ser array (OR).
- RequireAuth: solo sesión hidratada (/inicio, /ssa/evaluar/:templateId)
- /compartido/:token: PÚBLICO
- Home de todos: /inicio. /portal → /inicio. /doctor/consulta → /agenda.
